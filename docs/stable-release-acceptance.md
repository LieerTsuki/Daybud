## 环境修正与证据

API26/28准备脚本初次被数据库规范路径保护拦下。实际确认`/data/user/0`与`/data/data`是同一设备/inode后，只对固定模拟器改用后者的精确路径；保护保留，重试准备通过，应用未修改。

API35在未显式sync的模拟器退出/重开后，旧包安装文件丢失，但数据库仍在；版本保护在签名升级前中止。用完全相同旧APK执行install-r修复测试环境，没有清库；重新核对16张表、自增序列、旧包字节与旧签名后再执行正式覆盖。加入显式sync后，又对正式包完成一次冷启动持久性检查，结果通过。不能将环境中止记为已通过的签名升级轮次。

原始完整构建日志：`.tools/stable-full.log`；固定源码重新打包：`.tools/stable-committed-release.log`；签名回执：`.tools/delivery-stable/rizhiya-1.1.4.signing.json`。升级快照分别在`.tools/stable-upgrade-20261019`、`.tools/stable-api26-upgrade-20261019`、`.tools/stable-api28-upgrade-20261019`，公开汇总保留实际摘要与签名证明，不提交数据库或私钥。
