# 手机离线回顾改造：可行性与缺陷调查

日期：2026-10-22。基线为已发布 1.3.0/code14，源码 `1d6afb48fd0b2304c52328d7faccfe9733355ad4`。本文件记录早期调查；用户确认方案后已在开发分支实施，当前代码状态见[实施验收进度](offline-only-fast-reviews-acceptance.md)。没有新公开 APK 或新 Release。

用户最新要求为纯手机离线、移除云端、生成总结及具体参考建议，并减少等待。现有原文摘选不能满足该内容要求。Pura 70 上 13 篇失败、5 篇成功是用户提供的现象，尚无该手机的运行日志或连机测试。

## 已确认与尚未确认的原因

`PhoneAiRunnerAdapter` 在生成前获取模型租约，`LocalModelStore` 每次完整 SHA256 和 GGUF 检查。GGUF 大型词表元数据经过大量单字节文件读取；这是已复现的准备耗时点。导入路径使用文件输入流，不会自动改为下载。

`LocalGroundedPipeline` 每批最多涉及 8 篇，因此 13 篇至少两次推理，5 篇可能一次；实际文本长度和分词预算仍决定更多分片。`LocalAiGateway` 在模型获取后设置 180 秒超时，超时映射到通用 INFERENCE 提示，部分原生运行错误也是该提示。当前提示不能区别这些情况。以上可解释额外工作量和错误信息不足，但不能证明用户手机五分钟失败的唯一根因。

当前原生实现是基线 CPU、最多两个线程、每次重新加载模型/上下文；既未使用手机 NPU，也未选用 ARM dotprod 专用库。完整阅读输入和逐 token 生成都会消耗运算时间，文字交给本地模型不会变成即时响应。

## 模型文件读取原型

在 Windows、Intel Core i7-14650HX 上，用实际 396704416 字节的 0.6B 模型测试。临时副本仅为 GGUF 元数据加 64KiB 读取缓冲；全文件摘要、GGUF 和张量检查保留。

| 操作 | 原实现一次观察 | 缓冲原型一次观察 |
| --- | ---: | ---: |
| 导入并校验 | 51462 ms | 16134 ms |
| 获取租约并重新校验，第 1 次 | 8442 ms | 333 ms |
| 获取租约并重新校验，第 2 次 | 8595 ms | 867 ms |

原型运行模型目录、存储、设备能力与一个真实模型检查，共 28 项通过。这些数字属于早期临时实验；后续有界缓冲已接入开发分支，保留完整校验。上述观测未做隔离、随机顺序或多轮统计，不能据此承诺固定加速倍数；Windows/Robolectric 数字不是 Android 手机数字。

## 短总结质量实验

使用固定 b5501 原生 CPU、2 线程、4096 token 上下文和关闭思考模式。全部材料为 12 组人工合成日记，未使用用户正文或联网生成。比较短 JSON、纯文本、非思考采样、禁止空字符串，以及 0.6B/1.7B 共六种配置、63 次生成。全部结束标记不等于语义通过。

- 0.6B 短 JSON 多次生成空总结；禁止空字符串后仍会输出标点或无意义文字。
- 0.6B 纯文本可生成自然句子，但三天材料经常只复述最后一篇；也出现遗漏补写日期、无来源的“未完成”描述、与笔记不相关的建议。
- 改用采样未消除这些问题；存在受日记中复制指令影响的建议。模型输出的文字没有被执行，也没有网络上传动作。
- 1.7B 在若干样例中覆盖更好，但仍把晚上聊天写为下午、给出残缺建议，或把多天材料压缩成缺少关键状态的主题词，未通过完整内容门槛。不能据此要求用户立即换模型。
- 1.7B 的三篇合计 1135 汉字样例，非空 JSON 候选在电脑原生程序内用时 16954ms，其中载入 600ms、输入处理与上下文准备 13450ms、生成 2903ms。输入处理占较大部分，缩短回答本身不能消除长日记阅读耗时。该计时不含 Android 模型租约校验、Binder、页面和保存流程，也不是 Pura 70 速度。

原始合成材料、各次结果、阶段耗时、模型及程序摘要和人工发现见 [机器可读证据](evidence/offline-only-fast-reviews-20261022-feasibility.json)。这不是“63 项质量通过”的验收报告；目前没有一个新协议通过完整质量门槛。

## 结论与实施边界

推荐先实施可验证的模型读取优化与错误分层，同时退役云端生成；新摘要协议采用短总结加两条具体建议，并严格控制输入/输出工作量。ARM 可选指令加速需保留基线兼容、独立探测和真机验证。不能只延长超时，也不能以换大模型代替性能验证。

本轮不发布声称修复的新 APK；尚无 ARM 真机速度证据，新生成协议质量也未通过。下一步实现范围、兼容方案和发布门槛见 [设计草案](superpowers/specs/2026-10-22-offline-only-fast-reviews-design.md)。
