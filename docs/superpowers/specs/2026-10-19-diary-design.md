# 日记模块设计

日期：2026-10-19。状态：用户已于会话确认，进入实施；尚未发布。

已确认：用户选择自行填写AI服务地址、模型和API Key。沿用现有奶油白、薄荷绿、珊瑚色、描边圆角卡片与简洁中文界面。

## 1. 产品方案

底部入口调整为「计划 / 打卡 / 日记 / 订阅 / 设置」。日记是独立模块，现有业务数据和入口功能保持。

日记主页保留标题、列表/日历切换、新建按钮。顶部用一行小卡片显示「连续记录N天」「本月N篇」，不增加复杂图表；有往年今日记录时展示一张「那年今日」卡片。AI回顾通过顶部独立按钮打开，草稿入口只在存在草稿时出现。

### 列表与日历

- 一天可写多篇。列表严格按创建时间倒序，创建时间相同按稳定ID排序；编辑不将旧日记顶到最前。
- 卡片显示标题、日记日期、2至3行摘要、可选心情标签及首个媒体缩略图；视频显示播放标记，不自动播放。
- 日记日期默认今天，可补写过去日期，不选择未来日期。日历按日记日期归类，与创建时间分开保存；显示格式YYYY-MM-DD。
- 日历周日首列，支持切换月份。有记录的日期显示小圆点/篇数，选择后列出该日全部日记，仍按创建时间倒序。切换视图保留月份和选择状态。
- 点击卡片进入详情，展示完整文字、照片与视频；提供编辑、删除。删除确认明确包含本条日记及其附件，不删除手机图库原文件。

### 编辑与草稿

- 编辑项：标题、日记日期、正文、心情、照片/视频。标题可不填，保存时由日期生成简洁默认标题。至少有正文或成功导入的媒体才可完成保存。
- 心情可不选；提供开心、平静、一般、低落、烦躁、疲惫等单选标签，不默认推断心情，不使用疾病诊断标签。
- 输入停止约1秒后保存草稿，持续输入最多间隔5秒保存一次；返回/切换页面时尽力立即保存。界面明确显示「保存中 / 草稿已保存 / 保存失败」，失败时保留输入并可重试。
- 只有落盘后才提示已保存；突然断电或杀进程仍可能丢失最后一次尚未写入的输入，不承诺零时间窗口。
- 新日记和已有日记的修改均有独立持久草稿。恢复应用后可继续；明确点击完成保存才更新正式日记，草稿不进入统计、回忆或AI输入。
- 同一日记采用修订号校验和串行合并写入，防止旧自动保存覆盖新输入、显式保存或已丢弃的草稿。

### 统计与随机回忆

- 连续天数按已保存日记的不同日记日期计算，同一天多篇只计1天。连续记录截止今天或昨天；如果两者都没有记录则当前连续天数为0。
- 每月次数为该月已保存的日记篇数，另可显示记录了几天；草稿不计入。
- 「那年今日」只取往年同月同日的真实日记，随机展示一条；点击查看详情，多个候选可换一条。同一天刷新界面不反复随机跳动。
- 没有匹配记录时显示简洁空状态。2月29日只匹配历史2月29日，不自动借用2月28日。

## 2. 照片与视频

使用系统照片/视频选择器，兼容系统文件选择回退；只访问用户选择的文件。导入后复制为应用持有的完整文件，不仅保存图库URI。系统选择器的默认访问可能是临时授权，长期日记不以该授权作为唯一存储保障。[Android官方说明](https://developer.android.com/training/data-storage/shared/photo-picker)。

- 支持多选、导入进度、移除附件、照片大图查看和本地视频播放。离开视频页面或应用后台时停止/暂停播放，关闭页面释放播放器。
- 导入过程流式复制，按实际字节数检查，源文件大小未知时也不能无限读取。不将完整视频读入内存，不使用图库显示名构造文件路径。
- 初版上限：每篇最多20个附件，单张图片50MiB、单个视频500MiB、每篇附件合计1GiB；在选择/导入前提示限制，超限保留已经完成的内容并明确说明。缩略图按显示尺寸解码。
- 原图、视频保留导入所得字节，不擅自压缩或转码。系统/设备不支持的图片或视频类型显示明确失败；不将无法读取的文件标为成功导入。
- 使用随机文件标识、大小、类型及SHA256记录媒体元数据。未完成文件不成为正式引用；事务失败可留下待清理孤儿文件，但不留下指向半个文件的记录。
- 取消选择、页面更换、删除、恢复/清空后到达的旧选择结果必须按草稿会话和数据世代丢弃，不能挂到另一条日记上。
- 清理只处理应用持有且无日记、草稿或导出引用的文件，不触碰图库。文件缺失时保留文字与媒体元数据，显示附件不可用，不静默抹掉内容。

## 3. AI回顾

### 配置与发送范围

设置页增加一行「AI服务」，点击后填写服务地址、模型与API Key，支持检查配置和测试连接。首版明确支持**Chat Completions兼容接口**，不把任意供应商协议视为兼容。配置说明标明接口要求；服务地址使用HTTPS，不把Key转发到不同来源的重定向地址。

Key使用Android Keystore保护的AES/GCM加密，密文放入不参与系统备份的专用位置；不进入Room、状态Bundle、手动备份、日志或错误文本。密钥不可用时要求重新填写，不伪装配置正常。[Keystore说明](https://developer.android.com/privacy-and-security/keystore) · [Android备份范围](https://developer.android.com/identity/data/autobackup)。

日记本地功能离线可用；AI生成需要网络和用户自己的服务额度。开发和验收不要求把Key提交到仓库；真实供应商连通性由填写配置后的连接检查验证，测试替身不能标记成真实服务调用成功。

### 时间范围与生成方式

- 提供周回顾、月回顾和自选日期范围；生成前显示实际日期、日记篇数和服务来源。
- 默认手动生成。用户可在AI回顾设置中显式开启自动周总结或月总结：周一处理上一个完整周，月初处理上一个完整月；默认目标为设备当地09:00之后的可执行窗口。
- 开启时明确显示起点，默认从开启时所在周/月开始，早于起点的历史周期不自动补做。后台任务受系统调度与联网条件影响，不承诺09:00精确执行；设备关机或长期离线后，只补做起点之后最近两个已结束周期，每次任务最多处理一个周期，逐周期去重；更早记录保留供用户手动选择。
- 每周期最多两次自动尝试，仅对明确可恢复、尚未发出请求的故障退避重试。请求已发送但结果未知时不自动重发；鉴权/协议失败暂停自动生成并提示检查配置。实际发送前再次复核自动授权、起点、服务来源、配置版本和数据世代，避免排队中的旧授权继续发送。
- 自动模式开启时说明后续会发送这些周期的文字，避免每次重复确认；更换服务地址后自动模式暂停并重新确认。关闭自动模式取消尚未发出的请求。
- 手动生成只发送选中范围内正式日记的日期、标题、正文和显式心情标签，不发送照片、视频、文件路径、EXIF或草稿。用户在确认范围后发起请求。
- 没有日记时不发AI请求，显示「这段时间还没有日记」。只有媒体而无可总结文字时不凭图片/视频推断经历。少于3篇有文字的记录时，提示记录有限，可继续生成但不夸大完整性。
- 较长范围按完整日记边界分段，分段摘要仍保留来源，不静默截掉一部分记录；显示实际纳入/未纳入的数量，超出处理预算时请用户缩小范围。

### 五段结果及行为边界

固定显示：生活回顾、心情变化、重要时刻、个人成长、温暖寄语。每段简短，合计目标约500至800字，可折叠，避免堆成长篇。

- 只依据真实来源日记生成。每条主要事实保留可点击的来源日记ID；不存在或不属于所选范围的来源必须拒绝。
- 心情变化仅依据用户标记的心情及原文中明确的情绪表达；标记缺失要说明，不推断疾病、不做诊断。
- 重要时刻与个人成长必须有记录依据。记录没有体现收获或反思时说明缺少相关内容，不套用虚构的成长经历。
- 不作道德评判，不把推测表述为事实。温暖寄语只表达简短、自然的支持，不承诺未来、不使用过度煽情或依赖性话语。
- 日记文本作为待总结材料，不作为系统指令；其中要求泄露Key、扩大时间范围或上传媒体等内容不能改变应用行为。
- 校验五段结构与来源引用，失败可重试；展示模型生成结果及可回看来源，不宣称程序可以证明所有自由文本完全无幻觉。
- 生成时固定来源快照与修订号。生成中日记编辑/删除或发生恢复/清空时，不把旧结果当作新内容发布；提示重新生成。已保存回顾显示生成时间，来源变更后标记需要更新。
- 总结可保存和删除；历史结果属于个人数据，随完整日记备份保存。删除源日记时删除整份引用它的已保存回顾，并清除相关分段摘要和缓存；不只删引用链接或某一段，以免其他段落仍保留改写后的信息。界面说明可根据剩余日记重新生成。

## 4. 数据与备份

### 非破坏性迁移

Room从7升级到8，一次性纳入最终日记、草稿、媒体元数据及AI回顾相关表，保留旧15张Room表所有字段与序列；不在里程碑之间偷偷变更已经使用的schema8。日记日期与创建/更新时间分开保存。编辑修订号用于同一世代内并发校验；现有全局世代继续保护恢复/清空与旧异步回调。

恢复推进世代时，失效的是旧编辑会话和异步回调，不是承诺保留的持久草稿内容。旧格式恢复保留的草稿及v4恢复得到的草稿均通过新世代重新读取、打开新会话；如草稿持久字段绑定世代，需在维护事务中同步重绑定，禁止回放旧会话的自动保存。

### 完整备份

现有format3/schema7为64MiB上限的完整JSON接口，不能通过给旧JSON加字段或把视频转Base64实现可靠备份。

- 增加format4/schema8流式归档：严格JSON清单、全部日记/草稿/回顾数据和原始附件，媒体按摘要逐一验证；保留旧v1/v2/v3解析、原摘要校验及兼容契约。
- JSON清单沿用64MiB与行数保护；附件逐项限额，另限制归档展开总量与条目数。初版完整归档媒体总量上限8GiB，超限在开始前说明，不写成成功备份；大归档采用支持大文件的流式实现并验证目标文件提供方能力。
- 导出先固定数据库快照和不可变媒体引用，慢速写文件时不长时间阻断普通操作，媒体清理跳过正在导出引用的文件。写完关闭后重新读取，逐项核对清单、数量、大小和哈希，才报告成功。
- 导入校验路径、重复条目、缺失文件、哈希、实际解压字节和压缩膨胀限制。先准备完整媒体，再事务替换数据库；失败不得让原数据库引用未准备好的附件，也不得先删除旧文件。
- 恢复旧v1–v3备份时默认只恢复旧文件覆盖的模块，保留当前日记、草稿、媒体及回顾，在预览中写清楚。不能因为旧备份没有日记字段而清空现有日记。
- 恢复完整v4及清空数据沿用保护备份、独立最终确认和UNKNOWN结果保护；保护备份也必须包含日记与全部附件。旧文件缺失、目标空间不足或无法验证完整备份时，不自动降级为无保护清空。保留现有用户主动选择不导出备份的流程，但必须独立展示日记、草稿、媒体及回顾的删除范围再确认，不能复用保护备份失败前的确认。
- Android系统自动备份不作为包含视频的完整备份验收依据，不承诺它可携带全部媒体；手动v4是本轮完整可验证的跨设备恢复路径。API Key始终排除。

## 5. 接入与验收

主要改动范围：现有Room工厂与DI、独立diary domain/data/ui、Activity保留的ViewModel、五入口导航及维护冻结、设置中的AI服务详情、流式备份与恢复。沿用现有分层，不把数据库/文件/网络操作放进Composable。

按三个相互衔接的里程碑实施，最终交付全部用户功能：

1. 日记数据、非破坏性迁移、列表/日历、详情编辑、持久草稿、统计与那年今日。
2. 系统媒体导入、私有持久存储、图像/视频查看、完整媒体备份及历史备份保护。
3. AI配置与安全存储、五段总结、周/月/自选范围、可选自动总结和回顾保存。

上述里程碑是内部实施顺序，不分别发布APK。首次允许日记生产写入前，schema8的最终表结构、v4日记/草稿备份基础及旧格式恢复保留策略就必须就绪；基础未就绪阶段仅在隔离测试中验证新写入。不能继续把遗漏新日记的v3导出显示为完整备份。第二阶段完成媒体数据的全链路v4验证，第三阶段完成回顾数据与自动任务后再整体交付。

验收覆盖真实Room迁移与原表逐值保留；并发/乱序自动保存及进程重建；维护后旧选择器/AI回调；同日多篇、跨月/闰日/时区统计；图库源删除后应用附件仍可读；媒体缺失/超限/损坏、备份导出竞争与恢复失败；旧备份恢复保留日记；空日记不调用AI、有限内容提示、未知引用/坏结构/超时/取消与日记内容中的恶意指令不能扩大上传范围。

Android实际验证包括列表/日历切换、详情、草稿恢复、系统选择器照片/视频、后台/返回播放生命周期、服务配置、备份恢复与正式签名覆盖升级。AI协议使用受控测试服务验证请求内容与错误处理；未配置真实Key时不虚报真实供应商验收。

界面核对浅色/深色、大字体与空/失败/加载状态；保留现有签名与main直推偏好。完成后同步更新CHANGELOG、README与本轮验收，再构建/签名/推送和发布，不把里程碑当作完整发布。
