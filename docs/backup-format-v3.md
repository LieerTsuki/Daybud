# 完整备份格式 V3（数据库 schema 7）

此页为1.1.x的冻结历史契约；1.2.0日记候选完整导出使用[V4流式归档](backup-format-v4.md)，恢复本页旧格式保留当前日记。V3契约为 `life-manager-backup`、`formatVersion: 3`、`schemaVersion: 7`。文件是未加密 UTF-8 JSON，采用现有规范化 JSON 的 SHA-256 校验；哈希只覆盖原始 `payload`，元数据和校验值不参与哈希。严格拒绝重复字段、未知字段、错误类型、无效枚举及损坏关系。

V2 的十张业务表和全部设置字段保持原样；V3 增加：

| 表 | 精确字段 | 关系与限制 |
| --- | --- | --- |
| `habit_trees` | `id` 整数、`habitId` 整数、`species` 字符串、`plantedAt` 毫秒整数 | `id` 为正主键；`habitId` 引用习惯；树种限 PINE/GINKGO/CHERRY/MAPLE/OAK/BIRCH |
| `habit_waterings` | `recordId` 整数、`treeId` 整数 | `recordId` 唯一且引用打卡；`treeId` 引用树木；打卡与树木必须属于同一习惯；每树至多20条 |

成长值从浇水关联条数计算，不导出冗余计数。未被关联的打卡保留为可用水滴；未来日期仍由应用在对应日期开放。快照、恢复和清空均涵盖新增两表。

V1/V2 导入先由各自历史编解码器检查原始格式、schema、哈希与完整约束，再转换到当前载体。旧文件哈希不会套用到新结构。每个旧习惯初始化一棵种子，`plantedAt` 使用其原 `createdAt`；有效 `tree:ENUM` 选择保留，其他旧图标按习惯 ID 的稳定非负模6选择树种。原打卡保持原样，不生成浇水关联。转换后的新增种子也计入行数和完整输出字节预算。

总体默认上限仍为64 MiB和100,000条业务及关联记录，包含林场两表；恢复前拒绝超限数据。维护事务保留本机世代规则及各自增表的高水位，包含 `habit_trees`。`Long.MAX_VALUE` 主键可导出救援，但不能作为自增表的恢复来源；耗尽或损坏的本机自增序列也阻止恢复与清空。任一写入或提交后校验失败均回滚业务数据、设置、序列和世代。

V1/V2 的历史格式文档及编解码器保持其原契约。旧版应用无法读取 V3 文件，不能以降级方式读取林场备份。
